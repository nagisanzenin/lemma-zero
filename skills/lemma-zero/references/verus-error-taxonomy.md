# Verus & Z3 Error Taxonomy (Actionable Diagnostic Mapping)

Every error returned by `lz check <file.rs>` maps deterministically to a concrete failure class and recovery move. Never blindly retry syntax edits when the failure class is mathematical.

| Class (`error_class`) | Verus / Rust Signature | Root Cause | Minimal Recovery Move |
| :--- | :--- | :--- | :--- |
| `SYNTAX_OR_TYPE` | `error[E0...]`, `expected ... found ...`, `cannot find value`, `mismatched types`, mode errors (`cannot call spec function from exec`) | Mechanical Rust/Verus syntax, import, ghost/tracked/spec mode mismatch | Fix local syntax/type only. Never alter original function signatures or specs. |
| `TRIGGER_INSTANTIATION` | `postcondition not satisfied` or `assertion failed` involving `forall`, `exists`, `Seq`, `Map`, `Set`, `=~=`, or opaque `spec fn` | Z3 knows the fact abstractly, but lacks a ground trigger term or extensional equality witness | Add minimal `assert(a =~= b)`, `assert(m.contains_key(k))`, `reveal(fn_name)`, `assert(...) by { ... }`, or `broadcast use` — do NOT add random unrelated asserts. |
| `NONLINEAR_ARITH` | `assertion failed` / `possible arithmetic underflow/overflow` with `*`, `/`, `%`, bit shifts (`<<`, `>>`, `&`, `|`) | Z3 linear arithmetic cannot decide nonlinear multiplication, division, or bitvectors automatically | Wrap sub-obligation in `assert(...) by (nonlinear_arith)` or `assert(...) by (bit_vector)` with ONLY the minimal local hypotheses inside `requires`. |
| `MISSING_LEMMA` | `postcondition not satisfied` on recursive/inductive spec, state-machine step, or multi-step invariant where local asserts fail twice | Structural induction or algebraic bridge lemma is missing (the No-Lemma Cliff) | STOP local patching. Formulate a self-contained helper `proof fn` with clean `requires`/`ensures` and verify it standalone via `lz verify-lemma` FIRST. |
| `PRECONDITION_FAIL` | `precondition not satisfied` at a callee or lemma call | Caller did not prove callee's `requires` clause | Inspect the exact failing `requires` line from `lz check` output and prove it just before the call (or strengthen an intermediate helper lemma). |
| `TERMINATION_FAIL` | `could not prove termination`, `decreases` failure | Recursive `proof fn` or loop lacks a well-founded decreasing measure | Add an explicit `decreases <measure>` (e.g. `s.len()`, `n`, `set.len()` with `finite()`) and prove strict decrease on the recursive branch. |
| `RLIMIT_TIMEOUT` | `rlimit exceeded`, `Resource limit (rlimit) exceeded` | Z3 quantifier instantiation blowup or monolithic proof body with too many irrelevant facts in scope | Decompose into smaller `assert(...) by { ... }` blocks or separate helper `proof fn`s to isolate the Z3 context, or use `reveal_with_fuel` / `#[verifier::spinoff_prover]`. |
| `CHEAT_VIOLATION` | Caught by `lz anticheat` (`ASSUME_CALL`, `ADMIT_CALL`, `EXTERNAL_BODY_ATTR`, `SPEC_OR_SIGNATURE_MODIFIED`) | Forbidden cheat or altered original spec | Immediately revert the forbidden construct and prove the obligation honestly. |
